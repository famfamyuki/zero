# ADR-0010 — AI-abundance product direction

Status: **Accepted**  
Date: **2026-09-11**

## Context

AI systems are improving rapidly at workflow construction, coding, refactoring, testing, and agentic execution. The exact arrival date or definition of AGI is uncertain and must not be frozen into Product contracts.

AgentGraph Studio therefore needs a durable Product position that remains useful even if basic workflow generation, code generation, and generic architecture suggestions become cheap and widely available from external AI systems.

The existing Product already points toward `Understand → Evaluate → Improve → Verify → Own`, deterministic Evidence, controlled semantic change, portability, revision provenance, user-owned runtime, and later runtime Evidence. The question is which of these should be treated as the durable Product role when generation itself becomes abundant.

## Decision

AgentGraph Studio will be designed under the durable assumption that **workflow generation and much of routine improvement may become commoditized**.

AgentGraph Studio will not define its long-term moat as:

- manual visual workflow construction;
- prompt/role composition;
- template selection;
- framework code generation;
- generic AI improvement suggestions;
- exclusive access to one evaluator model;
- mandatory proprietary hosted execution.

Instead, the durable Product role is an **independent engineering record, verification, change-control, portability, and ownership layer** around AI workflows, regardless of whether the initial artifact was authored by a human, generated by an AI, imported from an existing project, or iteratively modified by another agent.

The Product North Star remains unchanged:

```text
Understand → Evaluate → Improve → Verify → Own
```

The interpretation becomes explicitly AI-abundance-compatible:

```text
Human or AI-generated workflow
→ canonical/versioned semantics
→ deterministic analysis
→ inspectable Evidence + provenance
→ bounded AI evaluation
→ explicit proposal
→ controlled semantic change
→ re-verification
→ compatibility-aware portable build
→ user-owned runtime
→ optional sandbox/runtime evidence
→ design vs actual
```

Generation itself does not need to be AgentGraph-owned.

## Durable product responsibilities

AgentGraph should increasingly own the engineering lifecycle around the artifact:

- intent and constraint representation where available;
- workflow/revision identity and semantic provenance;
- deterministic facts and reproducible checks;
- `Known / Inferred / Unknown` preservation;
- deterministic / heuristic / external-dependent classification;
- evidence references and evaluator provenance;
- target capability and lossiness disclosure;
- semantic diff and stale-change protection;
- approval boundaries for semantic or consequential changes;
- build/test/sandbox observations when explicitly authorized;
- separation of sandbox evidence from actual Production/runtime evidence;
- portable artifacts and user-owned source/runtime;
- machine-readable interfaces for CI, IDE agents, coding agents, and future autonomous clients.

## Human and machine interaction model

The visual canvas remains a first-class human interface, but it is not the Product boundary.

Long-term, authorized machine clients may inspect, evaluate, propose, build, and re-verify through headless interfaces using the same domain contracts as the UI.

Human involvement should concentrate at decisions whose authority or consequences justify it rather than requiring manual interaction for every mechanical step.

This does not authorize silent semantic mutation. The existing semantic-change sequence remains:

```text
Proposal
→ Semantic Patch
→ Validation
→ Before / After Preview
→ User Apply
```

Any future relaxation of user-apply requirements for a bounded capability still requires the applicable Execution Gate and explicit authority decision.

## Independent verification principle

A generator's statement that its own output is correct is not sufficient evidence by itself.

AgentGraph should prefer independently inspectable evidence where practical, including deterministic analysis, target-capability checks, build/test results, sandbox observations, policy results, runtime evidence, revision identities, and artifact fingerprints.

AI reasoning may interpret that evidence but must not silently convert generated claims into observed facts.

## Rationale

If generation becomes abundant, the scarcity shifts from producing another workflow to answering whether a particular version is understandable, justified, safe enough for its authority scope, reproducibly verified, portable, and actually owned by the user.

This direction also reduces dependence on any single frontier-model vendor. Better external generators should improve the value of AgentGraph rather than make the Product obsolete, provided their outputs can enter a trustworthy import/semantic/evidence lifecycle.

The decision therefore reinforces existing Product principles rather than replacing them:

- Simplest Sufficient Architecture;
- Evidence Before Intelligence;
- AI advisory authority with capability-scoped expansion;
- no silent semantic mutation;
- no silent lossy conversion;
- user-owned source/runtime;
- provider/framework replaceability;
- configured expectation ≠ static evidence ≠ sandbox observation ≠ runtime observation.

## Consequences

1. **Builder remains useful but is not the strategic moat.** Visual authoring and templates continue to serve current users and first value, but future Product decisions should not assume manual construction remains the dominant interaction.
2. **Headless and machine-readable contracts become strategically important over time.** They remain roadmap-dependent and are not automatically selected by this ADR.
3. **Import/mapping value increases.** AgentGraph should be able to receive externally generated artifacts without requiring users to recreate them manually, subject to existing safety/lossiness rules.
4. **Verification/provenance value increases.** Revision identity, Evidence, sandbox/runtime separation, compatibility, and change provenance become increasingly central as external AI generation accelerates.
5. **AgentGraph-owned generation is optional.** It may be added where it improves user value, but must not become a lock-in prerequisite.
6. **Current Product and current Sprint do not change.** This ADR does not select a new packet, change Stage order, expand AI/Mutation Authority, enable managed execution, change commercial configuration, or bypass current paid-launch prerequisites.
7. **The Agentic Verification Workspace remains Long-term Vision / Conditional.** This ADR strengthens its strategic rationale but does not select or implement it.

## Alternatives considered

### Continue positioning around visual workflow construction

Rejected as the durable Product moat. Visual design remains valuable, but its differentiation is vulnerable if external agents can construct equivalent systems automatically.

### Compete primarily by having the smartest proprietary evaluator

Rejected as the durable boundary. Model leadership is volatile and provider-dependent. AgentGraph should make evaluators replaceable and preserve evidence/provenance around their output.

### Become a mandatory hosted runtime/control plane

Rejected as the default direction. This conflicts with user-owned source/runtime and creates unnecessary lock-in. Hosted capabilities may exist where separately justified, but must not be the only path to value.

### Pivot away from workflow architecture entirely

Rejected. The existing semantic/evidence/change-control architecture already provides a strong path toward verification and ownership in an AI-abundant environment without discarding current Product value.

## Migration / compatibility impact

No persisted schema migration is authorized by this ADR.

No current JSON, CrewAI export, Readiness, Execution Preview, Resource Analysis, import, Architecture Review, paid-access, analytics, accessibility, language, or responsive behavior is changed by this decision.

Future packets should use this ADR as a Product-strategy constraint when choosing between generation-centric features and verification/evidence/control/ownership foundations.
